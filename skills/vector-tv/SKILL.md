# Vector TV — Android TV без рекламы, без root и без прошивки

Репозиторий: [Osmosy/vector-tv](https://github.com/Osmosy/vector-tv).

Настройка существующей системы через ADB: отключить телеметрию, рекламные строки и
предзагруженный мусор, поставить свой лончер. Телевизор при этом **не перепрошивается**:
ничего не устанавливается в системный раздел, ничего не удаляется безвозвратно,
откат — обратные команды по записанному состоянию.

## When to Use

- «телевизор тормозит / показывает рекламу», «убери лишнее с Android TV»;
- надо поставить свой главный экран вместо Google TV / Mi TV / TCL;
- разбор и настройка ТВ-приставки (box) с Android TV или Google TV;
- надо снять инвентарь или вернуть телевизор в исходное состояние.

Не для этого навыка: Samsung Tizen, LG webOS, Roku, Vizio, Hisense VIDAA — там нет ADB,
отключать телеметрию приходится пультом (см. `references/ecosystem.md`).

## Шаг 0. Договориться с владельцем

Три вопроса до первой команды, иначе не начинать:

1. **Какие приложения нужны?** Список «что оставить» — от владельца, не от агента.
   Голосовой ассистент, Chromecast, обновления системы, HDMI-CEC — спрашивать отдельно:
   люди замечают их пропажу через неделю, а не сразу.
2. **Лончер меняем или только чистим?** Это две разные работы.
3. **Кто рядом с телевизором?** На экране придётся нажать «Разрешить отладку», а после
   отключения пакетов — проверить Wi-Fi, пульт и HDMI. Без человека физически у ТВ не начинать.

## Шаг 1. Включить отладку на телевизоре

| Что | Где |
|---|---|
| Режим разработчика | Настройки → О телевизоре (или Система → О телевизоре) → нажать на **Сборка** 7 раз |
| Отладка по USB | Настройки → Система → Для разработчиков → **Отладка по USB** |
| Сеть | там же, если есть «Отладка по сети» / «Network debugging» — включить |
| IP-адрес | Настройки → Сеть → записать `192.168.x.x` |

Android 11+ с беспроводной отладкой требует **сопряжения**: на ТВ открыть «Сопряжение
устройства через Wi-Fi», там показывают порт и 6-значный код, на компьютере:

```bash
adb pair 192.168.1.50:41234      # порт и код — с экрана ТВ, код спросят интерактивно
adb connect 192.168.1.50:5555    # после сопряжения порт 5555 работает
```

На Android 8–10 достаточно `adb connect 192.168.1.50:5555` и «Разрешить отладку?» на экране.

## Шаг 2. Бэкап до любых изменений (обязательно)

```bash
<skill-dir>/scripts/tv-inventory.sh inventory 192.168.1.50
```

Скрипт только читает и складывает в `tv-inventory-<метка>/`: `enabled.txt`, `disabled.txt`,
`home.txt` (кто отвечает HOME), `props.txt` (модель, Android, `ro.adb.secure`), `animation.txt`.
Коды: 0 — бэкап есть, 1 — не подключился, 2 — плохие аргументы.

Если скрипт не подходит — те же четыре команды руками:

```bash
adb -s 192.168.1.50:5555 shell pm list packages -e | sort > enabled.txt
adb -s 192.168.1.50:5555 shell pm list packages -d | sort > disabled.txt
adb -s 192.168.1.50:5555 shell 'cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME'
adb -s 192.168.1.50:5555 shell 'getprop ro.product.model; getprop ro.build.version.release; getprop ro.adb.secure'
```

`ro.adb.secure=0` — порт 5555 даёт shell любому в сети без подтверждения; после работы
отладку выключить.

## Шаг 3. Составить список на отключение

Сначала увидеть, что есть, потом решать:

```bash
adb -s 192.168.1.50:5555 shell pm list packages -e | sed 's/^package://' | sort
```

Что искать: `recommend`, `ads`, `analytics`, `telemetry`, `tracker`, `promo`, `store`,
`gamecenter`, `kids`, `music`, `video`, `news`, `sports`, названия бренда (`mitv`, `tcl`, `hisense`).

Готовые списки по моделям не выдумывать: они лежат в `examples/<бренд-модель>/tv.json`
у [cleanyourtv](https://github.com/Gathin23/cleanyourtv) (407 моделей, 106 брендов) — смотреть
только под свою модель и только как источник кандидатов.

Правило: кандидат попадает в работу, только если владелец сказал «не пользуюсь». Агент
предлагает список с назначением каждого пакета, владелец вычёркивает.

## Шаг 4. Отключать, а не удалять

```bash
adb -s 192.168.1.50:5555 shell pm disable-user --user 0 <пакет>
```

`pm disable-user` — тот же переключатель, что «Отключить» в настройках Android. Пакет остаётся
на месте, поэтому возвращается одной командой `pm enable --user 0 <пакет>`. `pm uninstall --user 0`
тоже технически обратимо (через `cmd package install-existing`), но восстанавливается хуже —
для деблоата берут disable.

По одному пакету, с проверкой состояния между шагами. Не пачкой в цикле без вывода: если что-то
сломается, надо знать, на каком именно пакете.

**Стоп-список — что не отключать никогда** (с причинами и номерами issue — `references/safety-and-restore.md`):

- всё из `^(android|com.android.systemui|com.android.shell|com.android.settings|com.android.tv.settings)$`;
- `com.android.(google.)?(permissioncontroller|packageinstaller|ext.services|ext.shared|modulemetadata)` —
  после отключения этих Mi TV Stick не загрузился (#884);
- `com.cltv.mal`, `com.mediatek.(tis|tv.service|tv.agent)` — Haier H50H5F ушёл в цикл перезагрузок (#1578);
- `com.android.location.fused` — TCL 43S5400A ушёл в цикл загрузки в recovery (#2803);
- пакет, который **сейчас отвечает HOME**, пока новый лончер не назначен (#239);
- `com.google.android.tungsten.setupwraith`, если Wi-Fi сеть принадлежит ему: при отключении
  Android удаляет сеть и телевизор падает с сети вместе с ADB (сначала «забыть сеть» и подключиться заново).

## Шаг 5. Лончер (если меняем главный экран)

Порядок важен: **сначала поставить новый, убедиться что он стартует, и только потом
отключать старый** — иначе телевизор остаётся без HOME.

```bash
adb -s 192.168.1.50:5555 install -r app.apk          # установить лончер
adb -s 192.168.1.50:5555 shell 'cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME'   # проверить, кто отвечает HOME
adb -s 192.168.1.50:5555 shell pm disable-user --user 0 com.google.android.tvlauncher   # отключить штатный — только после проверки
```

`cmd package set-home-activity <компонент>` на части прошивок есть, но ведёт себя
по-разному; надёжный путь — установленный лончер + отключённый штатный, как это делает
cleanyourtv.

Варианты лончеров (числа проверены 01.11.2026):

| Лончер | Что это | Цена |
|---|---|---|
| [cleanyourtv](https://github.com/Gathin23/cleanyourtv) | лончер 572 КБ в стиле Apple TV + скрипты деблоата; ★48 871, Python, лицензия не SPDX | собирается из исходников: JDK 17–22 + Android SDK 34 |
| [free-my-tv](https://github.com/simbasjungles/free-my-tv) | APK, Android 8+, Google TV / Android TV / LG / Samsung; ★5 642, MIT; 96 МБ памяти против 242 МБ (−60 %); кнопка возврата | готовый APK |
| [tvboxtools](https://github.com/smartago/tvboxtools) | менеджер HOME (переживает перезагрузку без accessibility), `tvlm --mcp` для агента; ★17, Apache-2.0 | готовый бинарник + MCP |
| FLauncher | открытый лончер, минималистичный | готовый APK |

## Шаг 6. Проверка после работы

Пройти глазами владельца, а не логом: перезагрузка, Wi-Fi на месте, пульт работает, HDMI-входы
переключаются, любимые приложения запускаются, звук есть, обновления системы не сломались.
Затем повторно снять инвентарь и сравнить с бэкапом — это и есть отчёт «что изменилось».

## Шаг 7. Откат

```bash
<skill-dir>/scripts/tv-inventory.sh restore 192.168.1.50 tv-inventory-2026-11-01T18-00
```

Скрипт включает только то, что было включено до работы (сверяется с `enabled.txt`), и печатает,
кто теперь отвечает HOME. Если штатный лончер остался отключён — включить его руками и
проверить `resolve-activity`.

## Диагностика уже установленного телевизора

Если ТВ уже стоит и «тормозит», ломать ничего не надо — сначала посмотреть снаружи:

```bash
python3 <skill-dir>/scripts/tv-probe.py 192.168.1.61 --bridge 192.168.1.70 --watch 12
```

Скрипт показывает линк кабельного порта на мосте, часы телевизора (= uptime, если там 1970),
открытые порты и TCP-отклик, а в режиме `--watch` — перезагружается ТВ или работает.
Креды моста берутся из netrc (`KN_NETRC`, по умолчанию `~/.config/keenetic.netrc`).

Порядок и ловушки — `references/diagnostics.md`: почему нельзя верить ICMP, почему у ТВ и моста
одинаковый MAC, почему часы 1970 — это отсутствие NTP, а не «сбитая дата», и что означает
набор открытых портов.

## Обновление прошивки

Обновление системы может вернуть штатный лончер и часть отключённых пакетов. Это нормально:
не бороться, а повторить шаги 2–5 по тому же списку — бэкап от прошлого раза остаётся годным.

## Что не работает (проверено по документации проектов)

- **Fire TV** — только половина с деблоатом: Fire OS не отдаёт HOME стороннему лончеру.
  На 2015 Fire TV Box (Fire OS 5) отказывают и `pm`-команды.
- **Китайские TCL** — часть моделей отказывается устанавливать любой сторонний лончер.
- **Samsung, LG, Roku, Vizio, VIDAA** — ADB нет вообще.
- **Критическая ошибка агента = кирпич.** Спасение — только recovery/сброс с пульта, поэтому
  стоп-список из шага 4 и бэкап из шага 2 не обсуждаются.

## Что проверено, а что нет

Проверено на этой машине: `adb 1.0.41 (34.0.5)` установлен и запускается; `tv-inventory.sh`
проходит `bash -n`, без устройства отдаёт код 1 с внятной причиной, без аргументов — код 2.

НЕ проверено: ни одна команда не выполнена на живом телевизоре — устройства в сети нет.
Команды взяты из скриптов cleanyourtv (`tools/disable.sh`, `tools/restore.sh`,
`launcher/build-and-install.sh`) и free-my-tv; стоп-список — из их же комментариев с номерами
issue. Первый прогон на реальном ТВ — вместе с владельцем и с бэкапом.

## Common Pitfalls

- **Отключил пакет, который отвечает HOME** → телевизор стартует в пустоту, а на Google TV
  setup wizard может забрать категорию и уронить system_server в цикл. Лечение: сначала новый
  лончер и проверка `resolve-activity`, только потом `disable-user` старого.
- **Отключил setupwraith на Wi-Fi** → Android удаляет сохранённую сеть вместе с пакетом, ТВ
  уходит с сети вместе с ADB. Лечение: «забыть сеть» на ТВ, подключиться заново (сеть станет
  принадлежать `android.uid.system`), и только тогда отключать — либо `FORCE_SETUPWRAITH=1` на Ethernet.
- **Скопировал чужой список пакетов** → у другой модели другой набор системных служб; ломается
  именно то, чего в своей прошивке нет. Лечение: список только из `examples/<своя модель>/`,
  остальное — кандидаты, а не приговор.
- **`pm uninstall --user 0` вместо `pm disable-user`** → возврат требует `cmd package install-existing`
  и версии APK, которой может не быть. Лечение: для деблоата только `disable-user`.
- **Отключил отладку до отката** → вернуть доступ можно только снова через меню ТВ и пульт;
  если лончер сломан, меню может быть недоступно. Лечение: отладку выключать последней, после проверки.
- **`adb devices` пусто после `connect`** → на экране висит «Разрешить отладку?», либо Android 11+
  ждёт `adb pair`. Лечение: посмотреть на экран ТВ, при отказе — `adb kill-server`, заново `pair`, `connect`.
